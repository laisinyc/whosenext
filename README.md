实现一个餐厅服务员排序小程序，要求如下

1. 程序配置
    1. 可以添加删除服务员名字
    2. 可以配置餐桌的代号和最多可坐人数
2. 早上开始前，勾选当天在职服务员
3. 初始化：按照当天勾选服务员的顺序排序
4. 当有客人来时候
    1. 分配当前服务员
    2. 当前服务员服务人数增加对应数量，记录桌号
5. 下一位服务员的排序规则
    1. 服务人数最少的优先
    2. 当服务数量相同时，按照初始化顺序自上而下选择
6. 共享桌处理
    1. 当人数超过5(不含)人时为共享桌
    2. 共享桌不记录人数，只记录桌号
7. 有时候客人会要求更改桌位或者临时增加人数，提供改动对应条目的popup
8. 桌位占位与释放
    1. 选择桌子并分配人数后，该桌在「客人到店」的餐桌列表里显示为红色“占位”（附服务员和人数），不能再被分配给新客人
    2. 再次点击占位桌，弹出 popup，可「释放占位」（客人离开）、「修改分配」或取消
    3. 释放只是让桌子重新可用，服务员已记录的人数、桌数、日志都不变；释放动作会写入日志
    4. 「撤销」或在修改 popup 中「删除」某条分配，该桌也会自动恢复可用
    5. 修改 popup 里换桌时，被其他客人占位的桌子不可选
    6. 服务情况里已释放的条目显示为淡色加删除线
9. 一天分成上午班 / 晚班
    1. 晚班从 16:30 开始（可在 config.js 的 `eveningStart` 修改），之前为上午班
    2. 当天的日志按时间自动分成上午班、晚班两部分显示；导出的 .txt 也分成两段
    3. 结束营业时，汇总分别给出全天、上午班、晚班每位服务员的人数、桌数、桌号（按客人入座时间归班次）
    4. 班次只用于记录和汇总，不会重新排序，服务人数仍按全天累计
10. 撤销 / 重做
    1. 「客人到店」卡片右上角有 撤销 ↶ / 重做 ↷ 图标按钮（桌面端也可用 Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z）
    2. 分配、修改、删除、释放占位都可以撤销和重做；鼠标悬停（长按）按钮可看到将要撤销/重做的是哪一步
    3. 撤销/重做会在日志里各留一条记录，日志本身不回退
    4. 最多保留 50 步；做了新的操作后，重做记录清空；结束营业后全部清空
11. 按钮图标：只有 撤销、重做 使用图标，其余按钮保持文字
\n12. 餐桌按平面图排列
    1. 「客人到店」和「修改分配」弹窗里的餐桌按钮，按餐厅俯瞰图的位置排列：S123 在第一行，A1-A6 第一列，B 系列第二列，C 系列第三列，E2、E1 第四列（B23、B45、C23、C45 各占两行）
    2. 排列在 config.js 的 `tableLayout` 里用文字描述（每行一个字符串，空格分隔格子，`.` 为空位，同一桌号占相邻格子即跨行/跨列），改完刷新页面即可生效
    3. 没写进 `tableLayout` 的桌子会排在下面；删掉 `tableLayout` 则恢复为普通顺序排列
13. 每位服务员显示当前占位（未释放）的桌数：在「今日服务情况」人数/桌数下方显示红色“占位 N 桌”，“下一位服务员”卡片里也有；释放占位后立即减少，日志的“当前人数”行里以 `占位N` 标出
14. 前台 / 服务员权限
    1. 服务员不需要登录，直接打开页面就是只读：只显示「分配」页（下一位、餐桌占位情况、服务情况、最近记录），没有页签栏，「今日上岗」「日志」「配置」都隐藏；也不能分配、修改、释放、撤销
    2. 前台点右上角「前台登录」，输入用户名和密码后为管理员，拥有全部操作权限；点「退出」回到只读。登录状态保存在本机，换账号密码后自动失效
    3. 账号密码写在 config.js 的 `admin` 里（默认 frontdesk / 123456，部署前请修改）；删掉 `admin` 则不需要登录
    4. 说明：这是纯前端静态页面，账号密码在网页代码里可以被看到，只能防止服务员误操作；数据保存在各自设备的浏览器里，不会在前台和服务员的手机之间同步（需要同步就要加后端）
15. 多设备同步（Firebase，可选）：让服务员的手机实时看到前台的分配情况
    1. 前台操作后自动写入云端，服务员（只读）和其他前台设备实时收到并刷新；右上角显示同步状态（已同步 / 离线 / 同步失败），服务员页面会显示“数据更新于 hh:mm:ss”
    2. 断网时前台仍可继续操作，恢复网络后自动上传；服务员断网时显示最后一次收到的数据
    3. 同步开启后，前台改用 Firebase 账号（邮箱 + 密码）登录，config.js 里的 `admin` 账号密码不再使用；写入权限由 Firebase 规则限制为前台账号，服务员只能读
    4. 同时只用一台前台设备操作（多台同时改，以最后一次写入为准）；撤销/重做只在本机
    5. `config.js` 的 `firebase` 全部留空 = 不同步（和以前一样，数据只在各自设备上）

## 开启多设备同步（一次性设置，约 10 分钟）

1. 打开 [Firebase 控制台](https://console.firebase.google.com/) →「添加项目」，随便起个名字（可以不开 Google Analytics）
2. 左侧 **构建 → Realtime Database →「创建数据库」**，选离你近的地区，安全规则先选“锁定模式”
3. 左侧 **构建 → Authentication →「开始使用」→ 登录方法 → 电子邮件地址/密码 → 启用**
4. 在 Authentication 的 **用户** 页点「添加用户」，填前台用的邮箱和密码（例如 `frontdesk@你的店名.com`，不用是真实邮箱）。**只创建这一个账号**
5. 回到 Realtime Database →「规则」，粘贴下面内容（把邮箱换成第 4 步的邮箱），点「发布」：
   ```json
   {
     "rules": {
       "whosenext": {
         ".read": true,
         ".write": "auth != null && auth.token.email == 'frontdesk@你的店名.com'"
       }
     }
   }
   ```
   这样所有人（服务员）可以读，只有这个前台账号能写，其他人拿到配置也改不了数据
6. 项目设置（齿轮）→「你的应用」→ 添加 **网页应用**（`</>` 图标），注册后把得到的配置填进 `config.js` 的 `firebase`：`apiKey`、`authDomain`、`databaseURL`、`projectId`、`appId`（apiKey 会出现在网页里是正常的，安全靠上面的规则）
7. 提交并发布更新（`git push origin main && git push origin main:gh-pages`，约一两分钟生效），前台打开页面点「前台登录」，用第 4 步的邮箱和密码登录；服务员直接打开网址即可看到实时数据

注意：数据（服务员名字、当天分配）存放在这个 Firebase 项目里，且“任何人可读”；如果不想公开，请不要把网址发给外人。

## 使用 Google 账号登录前台（可选）

登录弹窗里有「使用 Google 登录」按钮，也可以继续用邮箱密码。启用步骤：

1. Firebase 控制台 → Authentication → 登录方法 → **Google → 启用**（填项目公开名称和支持邮箱，保存）
2. Authentication → **设置 → 授权域名 → 添加域名**，加入 `laisinyc.github.io`（本地测试用的 `localhost` 默认已有）。不加的话线上点 Google 登录会提示“当前网址未加入 Firebase 授权域名”
3. 把前台用的 Google 邮箱加进 Realtime Database 规则的写入名单（多个邮箱用 `||` 连接），点「发布」：
   ```json
   {
     "rules": {
       "whosenext": {
         ".read": true,
         ".write": "auth != null && (auth.token.email == 'frontdesk@你的店名.com' || auth.token.email == '你的Google邮箱@gmail.com')"
       }
     }
   }
   ```
   不在名单里的 Google 账号即使登录成功也写不了数据
4. （可选）在 `config.js` 的 `firebase.adminEmails` 里写上允许的邮箱，不在名单里的账号登录后会被自动退出、也看不到前台界面；留空则不限制界面（写入权限仍由上面的规则控制）
5. 手机上如果弹窗被拦截，请允许该网站的弹窗；已安装到主屏幕的应用同样适用
16. 结束营业可恢复（防误删）
    1. 点「结束当前 / 重新开始」前会先确认；如果还有桌子占位中，确认框会提示还有几桌
    2. 结束时会把当天的完整数据（上岗顺序、每桌分配、日志）另存一份；24 小时内、还没开始新营业时，在「今日上岗」页顶部会出现“刚结束的营业可以恢复”，点「恢复营业」即可原样找回（并把当时存进往日日志的那份撤回）
    3. 如果误点“开始营业”后又立刻结束（这次是空的营业），不会覆盖之前还能恢复的那份
    4. 开启同步时，可恢复的数据也在云端，换一台前台设备也能恢复
    5. 「清空所有数据」需要输入“清空”二字才会执行
